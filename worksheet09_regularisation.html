Part 1

What overfitting really is

A model is not built to score well on data it has already seen. It is built to work on data it has never seen.

1.1What we actually want

Two students prepare for an exam with past papers. One memorises the answers to every past question. The other learns the method behind the questions. On the past papers both score 100%. On the real exam, only the second does well.

  • Training data is the past papers.
  • Test data is the real exam.
  • Generalisation is doing well on the real exam.
Key idea

A low training error is not the goal. A low error on new data is.

1.2Signal and noise

Real data is always pattern + noise. Two houses of the same size sell for different prices because of things we did not measure. The model cannot tell which part of a point is pattern and which is noise. It only sees the points.

A model that fits every point exactly has learned the noise too, and the noise will not repeat on new data.

1.4The same story in classification

In classification the model draws a decision boundary: the line that separates the blue ○ class from the red × class. A stray point, a red × sitting among the blue ○s, is noise. An overfit model draws an island around it, and new blue ○ points that land inside the island are then classified wrongly.

Key idea

Overfitting in classification looks like islands and sharp bends around individual points.

1.5How overfitting shows up in the curves

During training we measure the loss on the training set and on a separate validation set after every epoch. The space between the two curves is the generalisation gap.

  • Underfit: both curves stay high and close together.
  • Good fit: both curves are low, with a small gap.
  • Overfit: training loss keeps falling. Validation loss falls, reaches a lowest point, then rises.

1.6Why overfitting happens: three ingredients

  1. Too much capacity. The model has far more freedom than the data needs.
  2. Too little data. Few points to pin the pattern down.
  3. Training too long. Once the pattern is learned, the model starts chasing the noise.

1.7Where does overfitting come from? Big weights

Part 2

L2 regularisation

Until now the model only cared about the data loss. Now every weight has a price.

2.1Weights cost something

Total loss = Data loss + Penalty

Think of it as a budget. The model may keep a big weight only if that weight earns back more, in lower data loss, than it costs.

2.2The L2 penalty

Penalty = λ2 (w1² + w2² + … )
  • λ (lambda) is how expensive weights are. You choose it.
  • Squaring means big weights pay much more. A weight of 1 costs 1; a weight of 10 costs 100.
Try it by hand

λ = 0.1, so λ/2 = 0.05.

Weights [3, −1, 2]: sum of squares = , penalty =
Weights [30, −10, 20]: sum of squares = , penalty =

Show answer

14 → penalty 0.7. 1 400 → penalty 70. Ten-times-bigger weights cost a hundred times more.

Keras writes the penalty as λ Σw², without the ½. That changes the number you type, not the idea.

2.3The update rule, step by step

  1. Plain gradient descent. α is the learning rate.

    wnew = w − α ∂L∂w

  2. Add the penalty to the loss.

    Ltotal = L + λ2 w²

  3. Differentiate. The gradient of (λ/2)w² is λw, so a new term appears.

    ∂Ltotal∂w = ∂L∂w + λw

  4. Put it into the update rule.

    wnew = w − α ( ∂L∂w + λw )

  5. Rearrange: collect the two w terms.

    wnew = (1 − αλ) · w − α ∂L∂w

The step now has two parts:

  1. Shrink the weight a little: multiply by (1 − αλ).
  2. Take the usual step: subtract α ∂L/∂w.

Key idea

L2 does not forbid islands. It makes the model pay for them. An island around a single noisy point rarely pays for itself. A real pattern supported by many points does, so it stays.

2.6Two practical rules

Do not penalise biases. A bias only shifts the boundary; it cannot bend it. There are also very few biases.

Scale your features first. Suppose house size (around 100 m²) and number of rooms (around 3) matter equally, each adding about 30 to the output.

2.7A note on Adam

With plain gradient descent, “add L2 to the loss” and “shrink the weights each step” are the same thing (2.3). With Adam they are not: Adam rescales every gradient, and if the penalty sits inside the loss it gets rescaled too, so equal weights no longer shrink equally. The fix is AdamW, which takes the Adam step from the data gradient only and shrinks the weights separately.

Common mistake

Both of these put the penalty inside the loss. Use AdamW for true weight decay.

PyTorch

# L2 inside the loss (rescaled by Adam)
optim.Adam(params, lr=1e-3, weight_decay=1e-4)

# true weight decay
optim.AdamW(params, lr=1e-3, weight_decay=1e-2)

Keras

# L2 inside the loss (rescaled by Adam)
Dense(50, kernel_regularizer=l2(1e-4))

# true weight decay
optimizers.AdamW(learning_rate=1e-3,
                 weight_decay=1e-2)

The lab uses plain gradient descent with momentum, so its λ means exactly what 2.3 says.

What to notice
  • λ = 0.03 keeps the two arcs and no island closes, though the boundary still bends towards the mislabelled points. The validation curve rises far more slowly.
  • λ = 0.3 flattens the boundary to nearly a line, and the training curve stays high: underfitting.
  • The largest weight tracks λ: the stronger the penalty, the smaller it stays.
  • Try values on a log scale (0.003, 0.01, 0.03, 0.1) and choose with the validation readout, never the test score.

Part 3

L1 regularisation

A different price, and one very different consequence: weights that become exactly zero.

3.1A different price

Penalty = λ (|w1| + |w2| + … )
Worked example

The two costs side by side, leaving λ out.

w0.1110
L2 cost w²0.011100
L1 cost |w|0.1110

L2 barely charges for small weights and charges heavily for big ones. L1 charges every unit of weight the same, including the small ones.

3.2The update rule, step by step

Same flow as 2.3. The only change is the penalty.

  1. Plain gradient descent.

    wnew = w − α ∂L∂w

  2. Add the L1 penalty to the loss.

    Ltotal = L + λ |w|

  3. Differentiate. The slope of |w| is +1 for positive w and −1 for negative w: sign(w).

    ∂Ltotal∂w = ∂L∂w + λ sign(w)

  4. Put it into the update rule.

    wnew = w − α ∂L∂w − αλ sign(w)

Key idea

The new term does not depend on the size of w. Every weight moves the same fixed amount, αλ, towards zero at every step. L2 shrinks in proportion; L1 subtracts a constant.

3.3The push towards zero, L2 against L1

  • L2 push = λw. It gets weaker as w shrinks.
  • L1 push = λ sign(w). It stays the same size all the way to zero.

λ = 0.5.

A useless weight (∂L/∂w = 0) starts at w = 1, with α = 0.1 and λ = 2.5, so αλ = 0.25.

  • L2: multiply by 0.75 each step.
  • L1: subtract 0.25 each step, and stop at 0.

Key idea
  • L2 divides every weight. All get smaller, none becomes zero.
  • L1 subtracts a fixed amount. Weak weights become exactly zero. Strong weights lose less than under L2.

3.5What that buys: automatic feature selection

If an input is useless, L1 drives its weights to exactly zero and the model ignores that input. L2 leaves every weight small but alive.

3.6When to use L2, when to use L1

L2 is the default in deep learning.

  • Hidden neurons are not meaningful features. Deep networks spread a pattern across many weights, each contributing a little. L2 keeps all of them alive and small, which is exactly that regime.
  • Its effect changes gradually with λ, so it is easy to tune.
  • It is what “weight decay” means in every framework (with AdamW, 2.7).

L1 is a tool for specific jobs.

  • Feature selection on the first layer, when you suspect many inputs are useless.
  • Compression: a sparse model with most weights at zero is smaller and faster.
  • Its effect has a cliff: a λ that zeroes 90% of the weights may still overfit, and a slightly larger one may zero almost everything. Harder to tune.
  • With plain gradient steps a weight can jump back and forth across zero. Libraries handle this; the lab clips at zero.
  • Elastic net is L1 and L2 together, when you want a little of each.
What to notice
  • Even with 90% of the weights at exactly zero (λ = 0.003), the model still overfits. The few surviving weights are enough to build islands.
  • L1 only regularises here at λ = 0.03, and the boundary it leaves is coarser than L2's.
Why the result differs from L2

L2 at 0.03 keeps all 2 751 weights alive and small: a smooth boundary with no closed island, but it still bends towards three of the four mislabelled points, and validation loss creeps up to about 0.64. L1 at 0.03 keeps ten weights and sets the rest to zero: a tiny sub-network that can draw two arcs and nothing else, validation loss about 0.54.

Which is better here? L1, narrowly, because this problem needs very few weights. Two arcs is a job for a handful of neurons, and L1 found that handful. But look at how it got there: 0.01 zeroed 99% of the weights and still overfit, then 0.03 worked. That is the cliff of 3.6.

What would make L2 win? A finer search between 0.03 and 0.1, or a problem where many weights each carry a little signal, which is most real problems. There, zeroing weights throws useful signal away, and L2's gentle shrink keeps it.

Part 4

Early stopping

The simplest method of all: stop training before the model starts memorising.

4.1What early stopping is

Intuitively: training has two phases. First the model learns the pattern, and both losses fall. Then it starts memorising the noise: training loss keeps falling, validation loss stops falling and turns up. Stop at the border between the two.

Formally: measure the validation loss after every epoch. While it is still going down, keep training. When it stops improving, or the two curves start to separate, stop and keep the weights from the epoch with the lowest validation loss.

4.2Should we stop at the first bad epoch?

Validation loss is noisy. One epoch that is slightly worse than the last does not mean the model has started memorising. If we stop at the first rise, we often stop too soon.

So we wait. Patience is how many epochs in a row without a new best we allow before stopping. While we wait, we save the weights every time a new best appears.

  • Patience 1 stops after epoch 6 and restores epoch 5. It gave up too soon and missed epoch 7.
  • Patience 3 stops after epoch 10 and restores epoch 7, the true minimum.
  • Patience 5 finds the same epoch 7, at the cost of two more epochs of training.

4.3Always restore the best weights

When training stops, the weights in the model are the last ones, not the best ones. With patience 3 above, that is epoch 10 (loss 0.54) rather than epoch 7 (loss 0.50). The saved weights have to be put back.

Common mistake

Keras does not restore by default.

Keras

EarlyStopping(monitor="val_loss",
              patience=20,
              restore_best_weights=True)
# default is False: keeps the last weights

PyTorch (by hand)

if val_loss < best:
    best = val_loss
    best_state = copy.deepcopy(model.state_dict())
    wait = 0
else:
    wait += 1
    if wait >= patience: break
model.load_state_dict(best_state)

4.4Why early weights are simple

  • Weights start small, at initialisation, and grow gradually during training.
  • Early on, the biggest drops in loss come from the big, clear pattern, which the model closes quickly.
  • The noise is learned slowly, one point at a time, and needs many more epochs.
Key idea

Stopping early keeps most of the pattern and little of the noise. Fewer steps also means smaller weights, so early stopping ends up doing a job very similar to L2.

4.5Two notes

  • Early stopping is almost free. Use it nearly always, as a safety net alongside the other methods.
  • You chose the stopping epoch using the validation set, so that set has influenced the model. Keep a separate test set for the final score.
What to notice
  • The dashed line marks the best epoch so far. The run stops once it has waited patience epochs beyond it, and the boundary fades back to that epoch's shape.
  • Patience 5 quits at epoch 9 with a nearly straight boundary. Patience 50 waits, finds epoch 73, and keeps the arcs without the islands.
  • Switch restore best weights off and the run keeps the later, worse weights. Compare the validation loss.

Part 5

Dropout

Make memorising hard by switching neurons off at random.

5.1Neurons that lean on each other

The finely balanced big weights behind an island (1.7) usually involve several neurons working together, each correcting another's quirks. This is called co-adaptation. In a team where any member may be absent on a given day, nobody can rely on one partner. Everyone has to understand the work themselves.

5.2How dropout works

At each training step, every neuron in the layer is switched off with probability r, the dropout rate. A different random set is switched off every step.

5.3The scaling problem

Four neurons each output 1.0 and feed a sum. With r = 0.5, about half are off during training, so the next layer receives about 2. At test time all four are on and it receives 4: twice what it was trained on.

Key idea

During training, multiply every kept neuron by 1 / (1 − r). At test time change nothing: all neurons on, no scaling. One step is noisy, but on average training matches testing.

5.4Why it works (1): no neuron can lean on a partner

Any partner might vanish on the next step, so each neuron must learn something that is useful by itself. Fragile, finely balanced combinations, the building blocks of islands, never become reliable, and the model stops depending on them.

5.5Why it works (2): many networks in one

Every dropout mask gives a different smaller network, and all of them share the same weights. Three hidden neurons give 2³ = 8 possible networks; a hundred give 2¹⁰⁰. Averaging many different models cancels their individual mistakes, an ensemble, and dropout trains a huge one at the cost of a single network.

5.6Training mode and test mode

Dropout is on only during training.

Common mistake

PyTorch

model.train()   # dropout on
...
model.eval()    # dropout off: do not forget
with torch.no_grad():
    preds = model(x_test)

Keras

model.fit(...)      # dropout on
model.predict(...)  # dropout off, automatic

# Dropout(0.5) in the model definition

5.7Costs and surprises

  • Slower, noisier training. You usually need more epochs.
  • Small network + dropout = underfitting. A small network cannot afford to lose neurons. Add dropout to networks big enough to overfit.
  • Typical rates: 0.2 to 0.5 on hidden layers, 0 to 0.2 on inputs.
  • Surprise: with dropout, training loss can sit above validation loss. Training loss is measured with neurons switched off; validation uses the full network.
What to notice
  • The boundary jitters while training: a different set of neurons is off each step. It settles smooth.
  • r = 0.5 on the wide network gives the best validation accuracy in this sheet. r = 0.7 struggles to fit even the training points.
  • The narrow network with r = 0.5 underfits: it has no neurons to spare.

Putting it together

Diagnose before you treat.

6.1Read the curves first

What you seeDiagnosisWhat to do
Both poorUnderfittingBigger model, train longer, less regularisation
Train great, validation much worse and risingOverfittingMore regularisation, or more data
Both good, small gapHealthyStop tuning. Check the test set once.

6.2A simple recipe

  1. First get a model that can overfit. If it cannot fit the training data, regularisation will not help.
  2. Add early stopping with best-weight restore, as the safety net.
  3. Add one of L2 (with AdamW) or dropout. Tune it on a log scale, coarse first, then fine.
  4. Re-read the curves and the gap after every change.
  5. Report the test score once, at the end.

6.3Stacking has diminishing returns

Every method attacks the same gap. Once the gap is closed, adding another method only pushes the model into underfitting.

6.5Other tools you will meet later

  • More data: the best regulariser of all.
  • Data augmentation: make new training examples (flip or crop an image).
  • Batch normalisation: mainly speeds up training, with a mild regularising side effect.
  • Label smoothing: stop the model being 100% sure of its answers.

Explain in two or three sentences
  1. Why do small weights produce smooth decision boundaries?
  2. Why does L1 reach zero when L2 does not?

Show model answers

1. A neuron's output changes by about w per unit of input. With small w nearby inputs get nearly the same output, so the boundary cannot bend sharply or wrap a single point (1.7).
2. L2's push is λw and fades as w shrinks, so it approaches zero without arriving. L1's push is a constant λ that does not fade, so it carries the weight all the way (3.3, 3.4).
3. Weights start small and grow with training. Fewer steps means less growth, and the clear pattern is learned in the first steps while the noise needs many more (4.4).
